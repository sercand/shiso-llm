# Provenance

Where the code in this repository came from. This file and the Acknowledgements
section of `README.md` are the only places upstream projects are named (rule 15);
`scripts/api_gate.sh` checks that every workspace member has a row here.

Some of the CUDA kernels came from [antirez/ds4](https://github.com/antirez/ds4)
(MIT): the q4e kernels, and the adapter layers ds4 wrote around the vendored
llama.cpp and exllamav3 kernels. That is why the `VENDOR.md` files still use
the name "ds4" for the host project.

deviations: the label scheme past 26 options is shiso's - a list of up to 26 options is lettered `A`..`Z`, a wider one up to the official 255 is two letters throughout (`AA`, `AB`, ..), keeping only the pairs the server's vocabulary spells as one token, so how wide a list a server can label depends on its vocabulary and a list wider than its one-token pairs is refused by name - and `/v1/decisions` takes the same 255-option bound as `/v1/systemone`, `chat_template_kwargs` restricted to renderer-known keys, server-config refusals without a shiso analog are absent (the round-trip and label checks stand in), and containers in `input`/`question`/`state` render as key-sorted compact JSON, so an object may differ byte-wise from an upstream that preserves the client's key order, and media on `input` is a shiso extension - the upstream decisions surface pins text-only inputs;
